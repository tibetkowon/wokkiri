# 로컬 MVP 구현

## 화면과 기술 구성

모바일 화면 흐름은 시험 계정 선택 → 리그 목록·개설·참가 → 회차 안내·출석/기록 → 종합 순위 → 요청함의 답변·판정 → 변경 이력입니다.

Python 3.9 이상 표준 라이브러리 HTTP 서버, SQLite, HTML/CSS/JavaScript로 구현했습니다. 패키지 설치·빌드·외부 비밀키가 없습니다. 서버는 `127.0.0.1`에만 바인딩합니다. 이번 선택은 로컬 MVP 구성으로, 외부 운영 인프라를 확정하지 않습니다.

- `domain.py`: 한국 시간 일정, 점수, 참가 명단 고정, 기록 검증과 정정 상태 전이를 담당합니다.
- `app.py`: 로컬 시험 세션, 참가자 조회 권한, HTTP 입력 검증, SQLite 트랜잭션 저장을 담당합니다.
- `web/`: 모바일 화면과 폼을 담당합니다. 점수·권한은 서버에서 판단합니다.
- `tests/`: 점수·마감·권한·상태 전이·저장과 HTTP 경계를 검증합니다.

리그에는 참가자, 회차, 요청, 변경 이력이 있습니다. 회차에는 한국 시간 시작/마감 시각, 회원별 최종 기록, 기록 버전, 글·사진 안내가 있습니다. SQLite 단일 상태 행을 트랜잭션으로 읽고 저장합니다. 작은 로컬 사용을 위한 선택이며 실제 운영 데이터가 커지면 별도 테이블로 분리해야 합니다.

## 구현 기본값

아래는 기획의 미정 항목에 대한 이번 로컬 구현의 기본값입니다.

- 가람·나래·다온·라온 네 명의 가상 시험 계정만 사용합니다. 계정 전환은 인증이 아닌 로컬 역할 시험 기능입니다. HttpOnly·SameSite 세션 쿠키는 요청자의 시험 역할을 구분합니다. 서버 재시작 시 역할을 다시 선택하고, 기록은 유지합니다.
- 로컬 리그 목록에서 참가합니다. 시작일은 내일 이후로 생성하며, 설정한 시작일 00:00부터 명단이 고정됩니다. 첫 집계일이 이후여도 동일합니다. 별도의 참가 승인·탈퇴·강퇴는 추가하지 않았습니다.
- 새 일상 리그는 요일로 집계 날짜를 만든 뒤 각 날짜를 선택/해제합니다. 지정 리그의 라운드는 입력한 기간으로 연속 생성합니다.
- 시작 전 회차는 합산하지 않습니다. 시작 후 유형이 일치하면 N점을 포함해 잠정 계산하고, 마감 전임을 표시합니다. 실제 기록이 없으면 유형 불일치가 아닙니다.
- 완료형(For Completion)은 완료 또는 실패를 선택합니다. 실패는 같은 부문 완료자 다음 공동순위이며 출석만보다 앞입니다. 지정 횟수를 성공한 중량이 없으면 중량 기록을 등록하지 않습니다. 일상 와드는 출석만을 사용할 수 있고, 지정 와드는 미참여로 남습니다. 횟수 0회·시간형 미완주 0회는 허용합니다.
- 유형 불일치 중 마감 후 직접 수정은 실제 기록을 낸 회원이 유형·기록값을 고치는 경우만 허용합니다. 출석만 회원이 기록으로 바꾸거나 기록을 출석만으로 바꾸는 것은 요청 절차를 따릅니다.
- 시간형 완주 기록은 화면에서 분·초로 입력하고 초 단위 정수로 저장합니다. 이의 수락에는 사유가 선택이고 거부에는 필수입니다.
- 화면은 탭·회차를 바꿀 때마다 서버 상태를 다시 읽습니다. 조회 응답의 변경 이력에는 사진 원본 대신 유무만 담습니다.
- 화면 용어는 WOD, For Time·AMRAP·For Max Reps·For Load·For Completion(EMOM 등 완료가 목표인 WOD)을 씁니다. For Time에서 시간 안에 못 끝낸 경우는 DNF가 아니라 Time Cap(완료한 reps 기록)입니다. 저장 값(`time`, `amrap`, `reps`, `weight`, `done`)은 그대로입니다.
- 일상 WOD는 출석 버튼을 먼저 누른 뒤 기록 입력 폼이 열립니다. 출석은 출석만 기록으로 저장되고, 기록을 저장하면 같은 자리에 덮어씁니다. 마감 전에 기록을 다시 출석만으로 되돌리는 화면은 없습니다.
- 리그를 열면 순위 탭이 먼저 보입니다. 새 리그는 일~토 달력에서 시작일·종료일을 고르고 요일 전체 또는 날짜별로 켜고 끕니다. 공휴일·대체공휴일은 `web/app.js`의 `HOLIDAYS` 표(2026-12-25 ~ 2027-12-27, 2027년 월력요항 기준)로 기본 제외하며, 임시공휴일과 2028년 이후는 표를 갱신해야 합니다. 안내 문구는 해요체로 씁니다.
- 본인 정정·지연 제출 요청은 요청함에 "본인 정정", "지연 제출"로 표시합니다.
- 한 기록에 진행 중 요청은 한 건만 받습니다. 정정 제안은 전체 기록값이며 유형도 바꿀 수 있습니다. 판정자는 유지·제안 반영·무효 중 선택합니다.
- 요청 대상의 기록 버전을 저장합니다. 불일치 직접 수정 등으로 원본이 바뀌면 오래된 요청은 덮어쓰지 않고 해당 사실을 기록해 종결합니다. 필요한 경우 접수 기간 안에 새 요청을 작성합니다.
- 사진은 JPEG/PNG, 파일당 2MB 이하입니다. 서버에서 크기·형식 표식을 확인하며 안내 변경 전후와 함께 로컬 DB에 보존합니다. 이력에는 사진 본문 대신 저장 여부를 표시합니다. 삭제해도 변경 이력의 이전 사진은 보존됩니다.
- 안내 및 기록 저장은 버전으로 중복 탭의 덮어쓰기를 차단합니다. 모든 요청 반영과 결과 저장은 같은 트랜잭션 안에서 처리합니다. 점수는 조회 때 원본 기록에서 재계산하므로 불일치 발생·해소가 즉시 누적에 반영됩니다.
- 신규 접수 마감은 마지막 회차 마감 + 정확히 72시간이며 해당 시각부터 접수 불가입니다. 기존 요청 처리·불일치 수정은 그 뒤에도 허용합니다. 최종 확정 상태는 조회할 때 세 조건으로 계산합니다.

## 로컬 시험 순서

1. 가람으로 들어가 기본 리그의 오늘 회차에 기록을 저장합니다.
2. 어제 회차를 선택합니다. AMRAP/횟수형 불일치로 모든 점수가 보류되며 목록은 가나다순입니다. 가람의 유형을 횟수형으로 직접 바꾸면 마감 후에도 불일치가 해소됩니다.
3. 그제 회차에서 본인 정정·지연 제출 요청을 만들고 판정자를 지정합니다. 상단 시험 계정 전환으로 해당 판정자가 된 뒤 요청함에서 처리합니다.
4. 타인 기록에 이의를 접수한 뒤 작성자 계정으로 전환해 수락 또는 거부합니다. 수락은 즉시 종결하고, 거부는 지정 판정자가 처리합니다. 2명 리그 동작은 자동 테스트로 확인합니다.
5. 새 리그를 개설하고 다른 시험 계정으로 시작 전에 참가합니다. 등록 기간의 시간 경계는 자동 테스트에서 시계를 주입해 검증합니다.

## 운영 전 남은 작업

이 로컬 서버는 실서비스 인증·여러 기기 동기화·배포 서버를 대체하지 않습니다. 실제 회원에게 제공하기 전 회원 인증, 초대 접근 제어, 운영용 HTTPS 서버, 백업 및 이미지 저장 한도를 정해야 합니다. SQLite 파일에는 기록과 사진 이력이 있으므로 백업·접근 보호가 필요합니다. 현재는 운영 중 자동 마이그레이션과 장기 보존 정책을 제공하지 않습니다.

별도 결제·광고·코치 승인·다수결 점수·중량 보정·강제 중재·자동 패소는 구현하지 않았습니다.

- `python3 -m unittest discover -s tests -v`: 15개 통과했습니다. 점수·불일치·마감·72시간·권한·2명 리그·원본 버전·사진 이력·SQLite 저장·HTTP 출처 검증을 포함합니다.
- `node --check web/app.js`: 통과했습니다.
- Orca 내장 브라우저 390×844 모바일 화면에서 계정 전환, 분·초 시간 기록 저장, 불일치 회차 전체 보류 표시, 타인 이의 접수 → 작성자 거부 → 지정 판정자의 반영·종결, 순위·이력 표시를 확인했습니다. 화면 개편 후 리그 개설·참가와 사진 업로드는 브라우저에서 다시 확인하지 않았습니다. 화면 너비와 콘텐츠 너비가 모두 390px로 가로 넘침이 없었습니다.
- 실제 휴대폰, 외부 회원 인증, 인터넷 다중 사용자 환경은 검증하지 않았습니다. 자동 검증용 DB는 임시 디렉터리에 격리하고 삭제합니다. 브라우저 시험에서 만든 가상 리그와 기록은 로컬 DB에 남아 있습니다.
