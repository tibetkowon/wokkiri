# 로컬 MVP 구현

## 화면과 기술 구성

모바일 화면 흐름은 가입·로그인 → 리그 목록·개설·초대 링크 참가 → 회차 안내·출석/기록 → 종합 순위 → 요청함의 답변·판정 → 변경 이력입니다.

Python 3.9 이상 표준 라이브러리 HTTP 서버, SQLite, HTML/CSS/JavaScript로 구현했습니다. 패키지 설치·빌드·외부 비밀키가 없습니다. 서버는 `127.0.0.1`에만 바인딩합니다. 이번 선택은 로컬 MVP 구성으로, 외부 운영 인프라를 확정하지 않습니다.

- `domain.py`: 한국 시간 일정, 점수, 참가 명단 고정, 기록 검증과 정정 상태 전이를 담당합니다.
- `auth.py`: 아이디·PIN 가입과 로그인, 세션, 로그인 잠금, 복구 키를 담당합니다.
- `app.py`: 세션 쿠키, 참가자 조회 권한, HTTP 입력 검증, SQLite 트랜잭션 저장을 담당합니다.
- `web/`: 모바일 화면과 폼을 담당합니다. 점수·권한은 서버에서 판단합니다.
- `tests/`: 점수·마감·권한·상태 전이·저장과 HTTP 경계를 검증합니다.

리그에는 참가자, 회차, 요청, 변경 이력이 있습니다. 회차에는 한국 시간 시작/마감 시각, 회원별 최종 기록, 기록 버전, 글·사진 안내가 있습니다. SQLite 단일 상태 행을 트랜잭션으로 읽고 저장합니다. 작은 로컬 사용을 위한 선택이며 실제 운영 데이터가 커지면 별도 테이블로 분리해야 합니다.

## 구현 기본값

아래는 기획의 미정 항목에 대한 이번 로컬 구현의 기본값입니다.

- 가입은 아이디(영문 소문자·숫자·밑줄 4~20자, 소문자로 바꿔 비교, 사이트 전체에서 하나), 닉네임(12자 이내, 사이트 전체에서 겹쳐도 됨), PIN 숫자 4자리뿐이며 이메일 같은 개인정보는 받지 않습니다. 아이디는 로그인에만 쓰고 다른 회원에게 보여 주지 않습니다. 계정은 사이트에 하나라 여러 리그에 참여할 수 있습니다. 계정 닉네임 변경 기능은 없습니다.
- 리그에는 개설·참가 시점의 닉네임을 기록하며 한 리그 안에서는 겹칠 수 없습니다(정규화 후 대소문자 무시). 초대 링크로 참가할 때 겹치면 그 리그에서만 쓸 닉네임을 따로 정합니다. 화면의 회원 이름은 리그에 기록된 닉네임입니다.
- 로그인은 쿠키(HttpOnly·SameSite=Strict·1년)로 유지하며 서버에는 토큰의 해시만 저장합니다. PIN도 해시(PBKDF2)로 저장하지만, 4자리라 DB가 새면 금방 풀립니다. 실제 방어는 시도 제한입니다.
- 닉네임은 NFKC로 정규화하고 제어·제로폭 문자를 뺀 뒤 저장하고, 리그 안 중복은 대소문자 구분 없이 비교합니다. 한계: 모양만 같은 다른 문자(키릴 문자 등)는 막지 못합니다.
- PIN이나 복구 키를 합쳐 5번 틀리면 10분간 잠기고 변경 이력에 남습니다. 아이디가 없어도 같은 문구("아이디 또는 PIN이 맞지 않아요.")로 답합니다. 한계: 아이디만 알면 누구나 그 계정을 10분씩 잠글 수 있고, 가입 화면의 "이미 쓰는 아이디" 안내로 아이디 존재 여부는 알 수 있습니다.
- PIN을 잊으면 본인만 복구할 수 있습니다. 가입할 때 복구 키(`XXXX-XXXX-XXXX`, 헷갈리는 글자를 뺀 32자 중 12글자, 약 60비트)를 한 번만 보여 주고 서버에는 해시만 저장합니다. 복구 키로 새 PIN을 정하면 그 계정의 로그인 기기가 모두 로그아웃되고, 쓴 키는 폐기되며 새 키를 다시 한 번 보여 줍니다. 입력할 때 대소문자·하이픈·공백은 무시합니다. 다른 회원이 초기화 코드를 만들어 주는 기능은 사칭이 가능해 없앴습니다. 한계: PIN과 복구 키를 모두 잃으면 로그인해 둔 기기가 있어도 계정을 되찾을 방법이 없습니다(아래 재발급에는 현재 PIN이 필요합니다). 복구 키만 잃었다면 로그인해 있고 PIN을 알 때 재발급으로 새 키를 받습니다. 아이디를 잊은 경우의 안내도 없습니다(실제 사례가 생기면 정합니다).
- 이전 로컬 DB의 계정은 서버 시작 때 아이디가 채워집니다. 가상 회원은 garam 등이고, 그 밖의 계정은 아무도 모르는 무작위 값이라 로그인할 수 없습니다(내부 계정 번호는 리그 명단·이력으로 다른 회원에게 보이므로 아이디로 쓰지 않습니다). 복구 키도 없습니다. 중간 수정본이 아이디를 내부 계정 번호로 채워 둔 계정(아이디가 계정 번호와 같고 복구 키가 없는 계정)도 서버 시작 때 무작위 값으로 다시 바뀝니다. 복구 키가 있는 가입 계정은 아이디가 우연히 계정 번호와 같아도 바꾸지 않으며, 가입할 때는 계정 번호가 아이디와 같으면 번호를 다시 만듭니다. 로컬 시험 데이터에만 해당합니다.
- 복구 키 화면에서 확인(계속하기) 전에 새로고침하면 키를 다시 보여 줄 수 없습니다. 키 평문은 브라우저 저장소에도 두지 않고, 확인 전이라는 표시만 sessionStorage에 남겨 초대 자동 참가를 미루고 안내와 계속하기를 보여 줍니다. 이 안내 화면에서 PIN을 넣어 새 복구 키를 받을 수 있습니다.
- 복구 키 재발급: 로그인한 회원이 현재 PIN을 다시 넣으면(`POST /api/recovery-key`) 새 키를 한 번 보여 주고 이전 키는 폐기합니다. 로그인 기기는 그대로 둡니다. 리그 목록 아래 "복구 키 다시 만들기"와 위 안내 화면에서 쓸 수 있고, 복구 키가 없던 이전 계정도 이렇게 키를 받습니다. 틀린 PIN은 로그인과 같은 실패 횟수·10분 잠금을 씁니다. 한계: 확인 전 표시는 탭별이라 복구 키 화면에서 탭을 닫고 새 탭으로 들어오면 안내 없이 바로 진행됩니다. 이때도 로그인해 있으면 리그 목록에서 새 키를 받을 수 있습니다. 로그인된 기기를 손에 넣고 PIN까지 아는 사람은 키를 바꿀 수 있습니다.
- 없앤 기능인 회원 발급 PIN 초기화 코드의 이전 이력은 DB에 남기되 조회 응답과 이력 탭에서는 뺍니다.
- 시험 모드로 시작해도 가상 회원의 아이디·PIN·복구 키 값은 서버 로그에 출력하지 않습니다.
- 리그에는 초대 링크(`/?join=코드`)로만 참가합니다. 참여하지 않은 리그는 조회 응답에 나오지 않습니다. 시작 후에는 초대 링크로도 참가할 수 없습니다.
- `WOKKIRI_DEMO=1`로 실행하면 가상 회원(아이디/PIN garam/1111, narae/2222, daon/3333, raon/4444, 닉네임 가람·나래·다온·라온, 복구 키는 모두 `DEMO-DEMO-DEMO`)과 예시 리그가 생깁니다. 기본값은 꺼져 있고 배포 서버에서는 켜지 않습니다.
- 시작일은 내일 이후로 생성하며, 설정한 시작일 00:00부터 명단이 고정됩니다. 첫 집계일이 이후여도 동일합니다. 별도의 참가 승인·탈퇴·강퇴는 추가하지 않았습니다.
- 새 일상 리그는 요일로 집계 날짜를 만든 뒤 각 날짜를 선택/해제합니다. 지정 리그의 라운드는 입력한 기간으로 연속 생성합니다.
- 시작 전 회차는 합산하지 않습니다. 시작 후 유형이 일치하면 N점을 포함해 잠정 계산하고, 마감 전임을 표시합니다. 실제 기록이 없으면 유형 불일치가 아닙니다.
- 완료형(For Completion)은 완료 또는 실패를 선택합니다. 실패는 같은 부문 완료자 다음 공동순위이며 출석만보다 앞입니다. 지정 횟수를 성공한 중량이 없으면 중량 기록을 등록하지 않습니다. 일상 와드는 출석만을 사용할 수 있고, 지정 와드는 미참여로 남습니다. 횟수 0회·시간형 미완주 0회는 허용합니다.
- 유형 불일치 중 마감 후 직접 수정은 실제 기록을 낸 회원이 유형·기록값을 고치는 경우만 허용합니다. 출석만 회원이 기록으로 바꾸거나 기록을 출석만으로 바꾸는 것은 요청 절차를 따릅니다.
- 시간형 완주 기록은 화면에서 분·초로 입력하고 초 단위 정수로 저장합니다. 이의 수락에는 사유가 선택이고 거부에는 필수입니다.
- 화면은 탭·회차를 바꿀 때마다 서버 상태를 다시 읽습니다. 조회 응답의 변경 이력에는 사진 원본 대신 유무만 담습니다.
- 화면 용어는 WOD, For Time·AMRAP·For Max Reps·For Load·For Completion(EMOM 등 완료가 목표인 WOD)을 씁니다. For Time에서 시간 안에 못 끝낸 경우는 DNF가 아니라 Time Cap(완료한 reps 기록)입니다. 저장 값(`time`, `amrap`, `reps`, `weight`, `done`)은 그대로입니다.
- 일상 WOD는 출석 버튼을 먼저 누른 뒤 기록 입력 폼이 열립니다. 출석은 출석만 기록으로 저장되고, 기록을 저장하면 같은 자리에 덮어씁니다. 마감 전에 기록을 다시 출석만으로 되돌리는 화면은 없습니다.
- 리그를 열면 순위 탭이 먼저 보입니다. 새 리그는 일~토 달력에서 시작일·종료일을 고르고 요일 전체 또는 날짜별로 켜고 끕니다. 공휴일·대체공휴일은 `web/app.js`의 `HOLIDAYS` 표(2026-12-25 ~ 2027-12-27, 2027년 월력요항 기준)로 기본 제외하며, 임시공휴일과 2028년 이후는 표를 갱신해야 합니다. 안내 문구는 해요체로 씁니다.
- 본인 정정·지연 제출 요청은 요청함에 "본인 정정", "지연 제출"로 표시합니다.
- 한 기록에 진행 중 요청은 한 건만 받습니다. 정정 제안은 전체 기록값이며 유형도 바꿀 수 있습니다. 판정자는 유지·제안 반영·무효 중 선택합니다.
- 요청 대상의 기록 버전을 저장합니다. 불일치 직접 수정 등으로 원본이 바뀌면 오래된 요청은 덮어쓰지 않고 해당 사실을 기록해 종결합니다. 필요한 경우 접수 기간 안에 새 요청을 작성합니다.
- 사진은 JPEG/PNG, 파일당 2MB 이하입니다. 서버에서 크기·형식 표식을 확인하며 안내 변경 전후와 함께 로컬 DB에 보존합니다. 이력에는 사진 본문 대신 저장 여부를 표시합니다. 삭제해도 변경 이력의 이전 사진은 보존됩니다.
- 안내 및 기록 저장은 버전으로 중복 탭의 덮어쓰기를 차단합니다. 모든 요청 반영과 결과 저장은 같은 트랜잭션 안에서 처리합니다. 점수는 조회 때 원본 기록에서 재계산하므로 불일치 발생·해소가 즉시 누적에 반영됩니다.
- 신규 접수 마감은 마지막 회차 마감 + 정확히 72시간이며 해당 시각부터 접수 불가입니다. 기존 요청 처리·불일치 수정은 그 뒤에도 허용합니다. 최종 확정 상태는 조회할 때 세 조건으로 계산합니다.

## 로컬 시험 순서

`WOKKIRI_DEMO=1 python3 app.py`로 실행합니다.

1. garam/1111로 들어가 기본 리그의 오늘 회차에 기록을 저장합니다.
2. 어제 회차를 선택합니다. AMRAP/횟수형 불일치로 모든 점수가 보류되며 목록은 가나다순입니다. 가람의 유형을 횟수형으로 직접 바꾸면 마감 후에도 불일치가 해소됩니다.
3. 그제 회차에서 본인 정정·지연 제출 요청을 만들고 판정자를 지정합니다. 로그아웃하고 해당 판정자의 아이디·PIN으로 로그인해 요청함에서 처리합니다.
4. 타인 기록에 이의를 접수한 뒤 작성자 계정으로 로그인해 수락 또는 거부합니다. 수락은 즉시 종결하고, 거부는 지정 판정자가 처리합니다. 2명 리그 동작은 자동 테스트로 확인합니다.
5. 새 리그를 개설하고 초대 링크로 다른 계정이 시작 전에 참가합니다. 등록 기간의 시간 경계는 자동 테스트에서 시계를 주입해 검증합니다.

## 운영 전 남은 작업

아이디·PIN 로그인, 복구 키, 초대 링크는 구현했지만 이 로컬 서버가 배포 서버를 대체하지는 않습니다. 실제 회원에게 제공하기 전 운영용 HTTPS 서버(쿠키 Secure 옵션 포함), 가입·로그인 요청의 접속 주소별 제한(가입 도배와 계정 잠금 장난 방지), 백업 및 이미지 저장 한도를 정해야 합니다. SQLite 파일에는 기록과 사진 이력이 있으므로 백업·접근 보호가 필요합니다. 현재는 운영 중 자동 마이그레이션과 장기 보존 정책을 제공하지 않습니다.

별도 결제·광고·코치 승인·다수결 점수·중량 보정·강제 중재·자동 패소는 구현하지 않았습니다.

## 이번 검증 결과
